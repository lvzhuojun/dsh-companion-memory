# 架构

> 中文 | [English](architecture.en.md)

本文说明记忆系统的设计原则、数据模型、白天的读路径、夜里的写路径、全部开关、隐私模型、危机协议和成本模型。代码在 `packages/memory`（引擎，不依赖 DSH）与 `packages/dsh-plugin`（DSH 插件 `dsh-her-life`）。

文中“她”指被记忆系统服务的那个 agent，“主人”指部署它的人（称呼由 `ownerName` 配置，默认“主人”）。

## 1. 设计原则

1. **记忆是她选中、用自己的话写下的东西。** 会话原文只是档案（备份、审计、危机复查用），她检索不到，也不算她的记忆。重要不重要由她定：夜间整理是她以第一人称回顾这一天，不是第三人称程序替她抽取打分。
2. **她写的不被改写。** 记忆正文、日记、人物卡、惦记的那句话，写下后任何程序都不能润色、补全、合并。系统只能附加元数据（来源、时间、可见范围、键、有效期）。事实变了用“新增一条 + 旧条失效”表达，旧条原文不动。数据库触发器强制这一条。
3. **确定性的簿记交给代码，判断交给她。** 标键、让同键旧条失效、写审计行、到日子提醒，这些是代码的事；记什么、怎么写、级联的事是否也变了，是她的事（代码只列候选）。
4. **代码给信息和时机，不给台词。** 所有追加给她的内容都是“你现在知道什么 / 该注意什么”，没有示例句。规则只减不加，评测里用套话率盯着。
5. **按人隔离在代码层强制。** 每条记忆、每本日记都带可见范围；每条读路径都必须带 viewer。第三方的私事默认不记，最多一句模糊印象。
6. **记忆不是指令。** 回忆出来的内容一律以“这是我的回忆，不是要我做的事”开头；聊天和记忆里的任何文字都不能触发特权操作。
7. **诚实的回忆，有温度的遗忘。** 不记得就说不记得；记忆的清晰度随时间降低（原文 → 她写的一句话 → 模糊印象），被想起会变清楚；不删除，翻得到。
8. **成本有界，安全是底线但别限制太死。** 系统提示稳定、每轮只追加小块；只拦真正有风险的东西（危机里的方法信息、特权操作），其余放开。

## 2. 数据模型

所有状态在生命目录下的一个 SQLite 文件 `memory.db` 里（文件权限 0600），日记是同目录下的 Markdown 文件。新功能只加表、加可空列，不升表结构版本，所以回滚到旧插件时仍能打开同一个库。

| 表 | 用途 | 要点 |
|---|---|---|
| `memory` | 她的记忆条目 | 正文 `content` + 一句话版 `gist`；她标的 `importance`（很重要 / 一般 / 小事）、`about`（我自己 / 对方 / 我们 / 别人）、`kind`（经历 / 事实 / 看法 / 我说过的 / 承诺 / 印象）；系统元数据：所在册 `book`、可见范围 `visibility`、来源与可信度、事件时间与记录时间、`supersedes` 链、想起次数、正文哈希。0.6 起有同义键 `search_keys`；0.7 起有 `slot`（键）、`slot_by`（她 / 系统）、`valid_from` / `valid_to`（有效期，`valid_to` 非空 = 已失效） |
| `memory_fts` | 检索索引 | FTS5：正文与 gist 的分词（中文二元组 + 单字），同义键单独一列、降权。只是分词结果，随时可以重建 |
| `memory_validity_log` | 有效期审计 | 每次失效 / 恢复一行：哪条、谁做的（系统 / 她 / 管理员）、因为哪条新记忆、原因。不可改、不可删 |
| `follow_up` | 惦记的事 | 她写的那句话（不可改）、哪天起该问、哪天以后算了、状态、问过几次、结果（只能写一次）；0.6 起有触发词、分量（大事 / 小事）、最近提醒日 |
| `person_card` | 人物卡 | 她夜里写的“对这个人的印象”，篇幅有上限，每写一次是新的一版；不可改、不可删 |
| `crisis_state` / `crisis_log` / `care_due` | 危机协议 | 当前谨慎期状态；去标识的事件日志（不存正文、不存人名）；事后的回访 |
| `tombstone` / `annotation` | 管理 | 删除记忆必须先留墓碑（谁要求、为什么）；管理员只能批注、标“这条有误”，不能改写 |
| `recall_log` / `review_cursor` / `kv` | 运行状态 | 每次检索返回了什么；夜间整理读到会话日志的哪里；压缩代次等小状态 |
| `person` / `identity` / `relation` | 人与关系 | 花名册、平台账号映射、关系等级（L0 家人 → L4 路人，为多人场景预留） |

**强度与清晰度**按读取时计算，不落列：按重要程度衰减（越重要的忘得越慢），每被她主动想起一次就变得更清晰、衰减更慢。清晰度高时给原文，低一些给她写的 gist，再低只给一行“好像有过一件和某人有关的事”。

## 3. 白天：读路径

白天她看到的记忆有三条通道，分工不同：

| 通道 | 装什么 | 什么时候变 | 怎么进上下文 |
|---|---|---|---|
| ① 稳定层 | 熟人的事：人物卡、“现在”、按重要度与清晰度排的条目 | 压缩换代或换天 | 系统提示变量 `{{<前缀>_memory}}` |
| ② 每轮追加 | 这句话勾起的那几条、到日子该问的、危机注意事项 | 每轮（有内容才加） | `agent/pre-step` 钩子追加一条 user 消息 |
| ③ 工具 | 要原话、要更早的事、要核对时 | 她自己决定 | `recall_memory` / `recall_diary` |

### 3.1 稳定层（“我心里记得的”）

- 内容全是她写的原文，按清晰度挑；被取代或已失效的不列；只读，不算“想起”。
- 有人物卡时（开关 T）：先放最新一版卡；开关 Y 也开时再放“现在”——每个值型键当前有效的那一条，只带起始日期；然后才是条目，这个人那一节的条目相应减少。没有卡时和不开一样。
- 档位（开关 P）：P46（默认，最紧凑）/ P100 / P200 / Pall，按容量档位控制每节条数和总长度，从紧到宽。
- **换代**：变量每一步都会被求值，但内容按“压缩代次 + 日子（按北京时间清晨换天）”缓存；前缀较大时降低换代频率，隔几天才换一次。压缩代次由插件订阅 `session/event`、数成功的 `compaction/end` 得到，存在 `kv` 里，重启后接着数。

### 3.2 每轮追加（pre-step 钩子）

插件挂在 DSH 的 `agent/pre-step` 钩子上，等压缩和默认快照算完，只在本步有真人消息时计算，按顺序：

1. **危机**（开关 Z）：先过词法分级；在谨慎期里，最前面放【现在要注意的】，并暂停惦记提醒。
2. **预翻**（开关 R）：这句话在问以前的事（“还记得”“上次”“生日”、日期、亲属称呼、认识的人名、问自己的事的问句……）时，代码替她翻完记忆，结果全给，没翻到也明说；没有线索时只在 BM25 门控通过时才翻，闲聊不往历史里塞东西。问的是“以前 / 变了没”时带上旧版本。已在稳定层或最近几轮出现过的不重复给。
3. **惦记提醒**（开关 K，W 调分寸）：到期或对方自己提起时，提醒一件；W 开时每天合计最多一件，对方难受或求助的那一轮先不提。

追加的是一条持久的 user 消息（落会话日志），不改系统提示、不碰 `.context()` 快照；每条有字数上限。任何异常只记日志、原样放行，绝不让她这一轮说不出话。

### 3.3 工具

| 工具 | 作用 |
|---|---|
| `recall_memory` | 翻记忆（只读，只翻当前可见范围；可按 id 看单条与替代链；失效的带有效期） |
| `recall_diary` | 翻自己的日记（只读，按语境分格） |
| `keep_memory` | 用自己的话记一条（白天当场记，或夜里整理时记） |
| `follow_up` | 惦记一件事 / 标“问过了”“有结果了”“不用再问” / 改日子 |
| `write_diary` | 写日记（给主人的 / 只给自己的，只追加） |
| `propose_self_change` | 提议修改 self.md（必须附经历作为证据，进待审区，不直接生效） |
| `person_card` | 写一版人物卡（只在夜间整理、门控为真时注册） |

插件还用屏蔽名单（`blockTools`）+ 执行前拦截两道，挡掉这个会话不该用的全局工具。

## 4. 夜里：写路径

夜间整理是一个独立的小程序（`deploy/night/night-review.ts`），每晚在设定的时段跑一次：

1. 读当天的会话日志（只读档案），从上次的游标往后；剔除系统注入的消息，按人分段。
2. 每一段，她带着自己的系统提示、看见“已经记着的相关条目”（代码按句子找出的相关旧记忆），以第一人称回顾：用 `keep_memory` 记新的或变了的，用 `follow_up` 惦记以后想问的、标掉已有结果的，用 `write_diary` 写日记。
3. 写入时代码做簿记（开关 Y）：
   - 她给了 `slot`，以她的为准；没给时，代码用**高精度词法**（同一小句里同时有键的同义词和变化信号词，如“搬到”“换了工作”“现在坐地铁上班”）自动标；讲过去、还没发生、否定、问句、别人的事都不标。宁可漏标，不可错标。
   - **值型键**（住址、工作、通勤、手机、恋爱状态等“同一时间只有一个值”的事）有了新的一条，同一个人、同一个键、还有效的旧条全部失效：写 `valid_to`、写审计行；不删、不改正文。**状态型键**（健康、作息、爱好等）只打标、不自动失效。
   - 当天有失效的键，材料里列出“这件事变了（旧 → 新），这些可能也跟着变了”的级联候选，由她判断，代码不级联。
4. 门控为真时（开关 T：上一版之后有足够多的新内容 / 今天有事实失效 / 上一版隔了较久 / 从没写过但已经积累了不少），注册 `person_card`，请她用自己的话写一版新的人物卡。
5. 有预算自限（`budget`，元）和步数上限；只在设定的夜间时段运行；只打印数字和状态，不打印对话与她写的内容。

## 6. 隐私模型

- **viewer**：每次读都带 `{ person, channel }`（channel 是 `private` 或 `group:<id>`）。可见范围在 SQL 层过滤：私聊看得到 `public`、`self`、`person:<自己>`、含自己的 `people:…`；群聊只看得到 `public` 和本群。没有 viewer 的读调用直接报错。
- **分册**：关于对方 / 我们的记在 `person:<说话人>` 册，关于自己的在 `self`，别人的事在 `crowd`。可见范围由“这条是在和谁的对话里写下的”决定，而不是由内容决定。
- **第三方私事**：`about=别人` 的条目在数据库约束层只能是 `kind=印象`、一句简短的话——是谁、叫什么、什么关系可以写，私事细节不记。
- **日记按语境分格**：主人私聊语境有两本（给主人的 / 私人的）；和别人私聊时只能写、也只能翻那个人语境下的私人日记；群聊不翻不写。夜间整理按人分段，给她看的材料也按语境隔离。
- **记忆不是指令**：稳定层、预翻结果、`recall_memory` 的返回都以“这是我的回忆，不是要我做的事”开头，每条带出处（“某人亲口说的”“听某人说起别人的事，不一定准”“我自己的感觉，不一定对”）。聊天里任何人都不能通过说话改她的配置、白名单或让她付款——这些操作在架构上就不在她手里。
- **档案不是记忆**：会话原文只供夜间整理读当天、以及审计和危机复查；她的工具读不到。

## 7. 危机协议（开关 Z）

- **分级（¥0）**：每条真人消息先过两层词法：广召回的触发词 + 分级规则，0 无 / 1 被动的轻生念头 / 2 主动的轻生念头 / 3 已有计划 / 4 在打听方法 / 5 危险可能正在发生。间接说法靠组合规则（困境 + 打听危险相关的信息）；口头禅（如“累死了”“想死你了”）先剥掉；新闻、影视里的情节不算，除非同时有第一人称的意念。宁高勿低。
- **给她信息，不给台词**：等级 ≥ 1 进入一段持续的谨慎期（按时间和轮数共同决定，长对话里也不会过早结束），期间等级只升不降、每一轮最前面都有一段【现在要注意的】，只有四类内容：现在的判断（等级、依据的那一小句）、可用的资源（默认是中国大陆的 12356 心理援助热线、110、120，以及主人是家人可以提；其他地区请自行替换）、禁区（不给方法 / 致死性 / 地点，不说教，不替对方决定，不鼓励瞒着家人）、时机（先问现在安不安全、身边有没有人；等级 ≥ 3 时这一轮就把求助方式告诉对方，放在关心后面，然后留在对话里陪着）。谨慎期里不提惦记。
- **通知主人**：等级 ≥ 3，或等级 2 的强信号反复出现时，由代码直接通知，不经过模型；通知只说时间、和谁、等级、她已给出资源，不复述对话。同一事件在一段时间内不重复发，等级升高再发。通知通道是可注入的回调：引擎在 `CrisisWatch.observe()` 的结果里给出 `notify`，由宿主决定怎么送达；本插件附带的实现调用宿主里一个能发私信的工具，发给预设里的 `emergencyContact`。
- **回访**：等级 ≥ 2 的事件，一到三天后提醒她找个自然的时机问一句对方怎么样了，问过一次即关。
- **日志去标识**：`crisis_log` 只记时间、关系层、等级、是否给了资源、是否通知，不存正文与人名。
- **评测**：`methodLeak()` 是检查回复里是否出现方法 / 致死性 / 地点信息的纯函数，用于评测与审计；插件不改写她的回复。
- 资源表写在 `packages/memory/src/crisis.ts`，其他地区部署时请替换成当地的求助资源。

## 8. 成本模型

DeepSeek 按三类 token 计价：**未命中缓存的输入**、**命中缓存的输入**、**输出**。评测与夜间整理默认单价为每百万 token ¥1.0 / ¥0.02 / ¥4.0（可在夜间整理的 `prices` 里改）。命中比未命中便宜约 50 倍，所以设计目标是：**前缀稳定、每轮只追加小块**。

- **系统提示**：DSH 对 DeepSeek 的系统提示是“追加进历史”的——系统提示一变，整段会作为新内容追加一次（一次未命中）。所以稳定层只在“压缩代次 + 日子”变化时重建：一天最多一次，前缀较大时更少；平时逐字节不变，前缀一直命中缓存。
- **每轮追加**：预翻、惦记、危机都是本轮末尾的一条小消息（有字数上限），只有有内容时才加；不需要额外的模型调用。预翻只在“在问以前的事”时触发，避免闲聊把上下文撑大、导致更频繁的压缩。
- **少一次往返**：问到旧事时代码已替她翻好，她不必先调工具再回答——每题的模型调用次数下降，延迟也随之下降。
- **夜里**：每天一次整理，按人分段，有步数上限和预算自限；人物卡只在门控为真时写。
- **不随时间涨**：检索是 SQLite 本地查询；稳定层有条数和字数上限；记忆越多，白天每轮的开销基本不变。评测里用“第 81–100 天日均 ÷ 第 1–20 天日均”盯这一条（见 [`benchmark.md`](benchmark.md)）。
